● Both problems found. The magazine one is more interesting than it looked.

  The magazine

  Your weapon's body comes from our .app, but the magazine on screen is a separate part entity attached at mag_slot — and it uses the part item's own appearance resource, not the magazine components inside the
  main .app. So moving our magazine mesh did nothing visible: the game was drawing the stock Pulsar magazine the whole time.

  I verified the shipped mesh really did move (bbox Y[-0.048,+0.029] Z[-0.149,-0.020] in the deployed archive), which is what proves it's a different magazine being rendered.

  Fixed by pointing the weapon's part presets at our part items via slotPartListPreset. Written as mutations (!remove the two stock entries, !append ours with explicit slots) so nothing else the Pulsar preset
  installs gets disturbed. Yaml-only change — the archive was already correct, so no rebuild.

  The optic and muzzle

  That one's my fault: the snippet I gave you used local ts = ... on the first line and reused it on the next two. Each CET console entry is its own scope, so ts was already gone — only the weapon was ever
  given. Use one self-contained line each:

  Game.GetTransactionSystem():GiveItem(Game.GetPlayer(), ItemID.FromTDBID("Items.WeaponSet_SMG"), 1)
  Game.GetTransactionSystem():GiveItem(Game.GetPlayer(), ItemID.FromTDBID("Items.WeaponSet_Scope"), 1)
  Game.GetTransactionSystem():GiveItem(Game.GetPlayer(), ItemID.FromTDBID("Items.WeaponSet_Muzzle"), 1)

  TweakXL created both records without errors, so they will appear (Backpack → Mods). I've also set the weapon to ship with our optic and suppressor already fitted, so a fresh copy shows them without any
  attaching.
